# 抖音解析算法修复复盘

> 记录时间：2026-08-13
> 范围：`services/api_go` 解析器（Go 后端）——分享链接解析 → 无水印视频下载 → 文案转写链路中的"解析"环节
> 触发问题：网页端报错「该作品是图文或不含视频，不能下载视频或提取口播」（`VIDEO_REQUIRED`）

---

## 一、背景与问题

**项目**：自托管的抖音内容提取工具。Go 后端 `services/api_go` 内嵌网页端，流程为：

```
分享链接 → 解析作品信息 → 下载无水印视频 → 提取音频 → ASR 转写文案
```

**故障现象**：提交抖音分享链接（如 `https://v.douyin.com/GkQbHe4KKnk/`）后，任务失败，错误码 `VIDEO_REQUIRED`，提示"该作品是图文或不含视频"。即解析环节没能拿到 `video` 类型 + 无水印视频地址。

**排查起点**：项目内 `cache/`、`cache2/` 各有一套"可工作"的 Python 抖音解析参考实现，均依赖 `_ROUTER_DATA → videoInfoRes → item_list[0]` 的静态 SSR 数据路径。

---

## 二、调查过程

### 2.1 参考实现逐一实测（结论：全部失效）

| 参考实现 | 依赖路径 | 实测结果 |
|---|---|---|
| `cache/douyin-video/scripts/douyin_downloader.py` | `_ROUTER_DATA → videoInfoRes` | 失效 |
| `cache2/script/douyin_resolver.py` | `_ROUTER_DATA` / `RENDER_DATA` | 安装 requests 后实测 → 「分享页未找到内嵌公开数据」 |
| 本项目 `internal/resolver/douyin.go`（改造前） | 同上 | 失效 |
| `wujunwei928/parse-video`（Go，2026-07-25 仍在更新） | 视频仍用 `videoInfoRes`；图集用 `slidesinfo` + 随机 a_bogus | 视频路径失效；图集端点实测返回空 |

### 2.2 抖音各域页面逐一探测

用多种 UA（iPhone iOS 17/26、Windows Chrome）抓取，标记 `videoInfoRes` / `RENDER_DATA` / `item_list` / `playwm` 全部为 **0**：

- `www.iesdouyin.com/share/video/{id}` → 仅 JS 壳（`itemId`/`query`/`ua`，无作品数据）
- `www.douyin.com/video/{id}` → `_$jsvmprt` JS 反爬门
- `m.douyin.com/share/video/{id}` → 同样仅壳
- 旧分享 API `web/api/v2/aweme/iteminfo` → `{"status_code":11110,"encrypt_data_miss"}`（已关闭）
- `web/api/v2/aweme/slidesinfo`（图集）→ 空响应

**结论**：抖音已**全局移除分享页 SSR 内嵌数据**，所有依赖静态 HTML 的解析方式彻底失效，与 UA、域名、签名无关。

### 2.3 找出真实取数路径（关键突破）

用**无头 Edge + CDP（Chrome DevTools Protocol）抓包**，观察真实浏览器渲染 `www.douyin.com/video/{id}` 时的网络请求：

- 页面实际调用 `https://www.douyin.com/aweme/v1/web/aweme/detail/?...&aweme_id={id}&a_bogus=...` 获取数据，返回 **200 + 完整 `aweme_detail`**（标题、作者、无水印视频地址等全都有）。
- 这就是市面上成功工具的**真实机制**：`detail API + a_bogus 签名 + ttwid cookie + 浏览器头`，而不是任何静态页面解析。

### 2.4 签名算法来源

从活跃维护中的开源项目 `LiChangZheng10086/doyin_ai_video`（2026-08-10 更新）找到 a_bogus 算法实现（TypeScript，引用自 Evil0ctal/Douyin_TikTok_Download_API 系）。算法为：

```
a_bogus = 自定义base64( 随机串[12B] + RC4(key="y", 签名体[38B + 浏览器信息 + 校验字节]) )
其中签名体由 SM3(参数字符串+"cus") 等哈希、时间戳、UA 常量按固定字节布局拼成
```

先在 Node + `sm-crypto` 验证算法可用，再移植到 Go。

---

## 三、根因分析（汇总）

1. **直接原因**：抖音移除 SSR 数据后，解析器只能拿到"空壳作品"（仅 `itemId`、无标题/视频/作者），Worker 判定非视频 → `VIDEO_REQUIRED`。
2. **间接原因**：项目及参考实现都停留在旧的 `videoInfoRes` 静态解析，没有跟随抖音迁移到 `detail API + a_bogus`。

---

## 四、方案确定与验证

### 4.1 三种候选方案

| 方案 | 说明 | 评估 |
|---|---|---|
| A. 纯 Go 移植 a_bogus + ttwid | 计算签名 + cookie 调 detail API | **选定**：轻量、无浏览器常驻、约 0.3s/次 |
| B. 无头浏览器全程渲染 | 每次用浏览器取数 | 抗改版但 2-4s/次、需浏览器常驻 |
| C. 第三方解析 API | 违反自托管定位 | 排除 |

### 4.2 决定性验证（裸 HTTP 客户端复现）

在同一会话内"抓新签名 → 立即裸 HTTP 重放"，拿到 76KB 完整 `aweme_detail`，证明**纯 HTTP 可复现**，不需要浏览器常驻。

### 4.3 最小参数集测试（逐项剥离）

用新签名 + cookies 逐项删除参数实测：

- 必须：`a_bogus`（无/随机都返回 403 `Blocked by ArgusSecurityPlugin Sign Invalid`）
- 必须：`ttwid` cookie（无 cookie → 空 200；仅 `ttwid` 即可，`s_v_web_id` 单独不行）
- 可剥离：`x-secsdk-web-signature`、`verifyFp`/`fp`/`uifid`、`timestamp` 参数

### 4.4 ttwid 获取机制调查

- ttwid 由浏览器 JS（webid SDK）生成，**不能从简单 HTTP 引导**；哈希带盐无法推导。
- `POST /ttwid/check/`（body `{"aid":6383,"service":"www.douyin.com"}`）可**续期**，但需携带已有 ttwid（1 年有效）。
- **关键发现**：抖音**首页不生成 ttwid**（仅 `__ac_nonce`/`s_v_web_id`/`__ac_signature` 等），必须导航到**视频/图集等完整应用页**才会触发生成。
- 结论：首次用无头浏览器引导一次 ttwid，之后纯 HTTP 快路径。

## 五、实现细节

### 5.1 新增文件（`services/api_go/internal/resolver/`）

| 文件 | 内容 |
|---|---|
| `sm3.go` | 纯 Go SM3 国密哈希（GB/T 32905-2016），零新增依赖，通过标准测试向量 |

| `ttwid.go` | `TtwidManager`：持久化（默认 `./data/douyin_ttwid.json`）+ `ttwid/check` 纯 HTTP 续期 + 无头 Edge/Chrome CDP 引导（`gorilla/websocket`） |
| `abogus_test.go` / `sm3_test.go` | 结构/向量单元测试 |
| `live_test.go` | 真实链路集成测试（`RUN_LIVE=1` 才跑） |

### 5.2 修改文件

| 文件 | 改动 |
|---|---|
| `douyin.go` | detail API 作为主路径；短链先跟重定向取 ID；空壳作品丢弃；detail 失败重试 3 次；分享页解析降级为兜底 |
| `safehttp.go` | 新增 `Request` 方法（自定义请求头/Cookie/请求体，仍走 SSRF 白名单校验） |

| `.env.example` | 补充新配置说明 |

### 5.3 关键代码要点

**detail API 请求参数**（固定顺序，签名与请求必须一致）：

```
device_platform=webapp&aid=6383&channel=channel_pc_web&pc_client_type=1&
version_code=170400&version_name=17.4.0&cookie_enabled=true&
browser_language=zh-CN&browser_platform=MacIntel&browser_name=Chrome&
browser_online=true&engine_name=Blink&os_name=Mac OS&os_version=10&
platform=PC&screen_width=1920&screen_height=1080&aweme_id={id}
```

**请求头**：Windows Chrome UA、`Referer: https://www.douyin.com/video/{id}`、`Accept: application/json, text/plain, */*`、`Cookie: ttwid=...`、`Accept-Language`、`Sec-Fetch-Site/Mode/Dest`。

**ttwid 生命周期**：

```
Get() → 有缓存且未过期？→ 直接返回
      → 有过期风险？→ POST /ttwid/check 续期（纯 HTTP）
      → 没有 → 无头浏览器引导（导航到视频页 → CDP 轮询 cookies 取 ttwid）
```

**无头浏览器引导 CDP 流程**（复用 `gorilla/websocket`，约 2-4 秒）：

```
启动 Edge --headless=new --disable-gpu --no-sandbox --remote-debugging-port={port}
        --user-data-dir={tmp} --no-first-run --remote-allow-origins=*
轮询 http://127.0.0.1:{port}/json 等 page 目标
连接 page WebSocket → Network.enable / Page.enable / Page.navigate(视频页)
轮询 Network.getCookies 直到出现 ttwid（超时 25s）
关闭浏览器
```

## 六、遇到的坑与解决

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | SM3 `ROTL(T_j, j)` 未取 `j%32` | 摘要与标准向量不符 | 改为 `rotl(t, uint(j%32))`，用标准向量 `sm3("abc")=66c7f0f4...` 验证 |
| 2 | **短链无 WorkID** | 短链 `v.douyin.com/xxx` 提取不到 ID，detail API 被整体跳过 → 走死路回退 | Resolve 里先跟重定向（`SafeClient.Get`）提取 ID 再调 detail API |
| 3 | **空壳污染缓存** | detail API 瞬态失败 → 回退返回"仅 ID 空壳" → `cache.Save` 覆盖了好缓存 → 后续任务永久失败 | 新增 `isEmptyShell`，空壳不返回、不写缓存 |
| 4 | 首页不生成 ttwid | 引导超时无 ttwid（首页只有 4 个 cookie） | 引导时导航到 `https://www.douyin.com/video/{id}` 完整应用页 |
| 5 | detail API 偶发限流 | 空 200 / 403（`Blocked by ArgusSecurityPlugin`） | 用新签名（含新时间戳+随机浏览器信息）重试 3 次，间隔 400ms |
| 6 | Go 测试缓存 | `go test` 结果 `(cached)` 掩盖了真实重跑 | 加 `-count=1` 强制重跑 |
| 7 | Python/Windows 路径 | Git Bash 的 `/tmp` 在 Python 中解析为 `C:\tmp` 不存在 | 统一用相对路径/`tempfile` |

## 八、经验总结

### 8.1 对抖音平台

1. **静态 SSR 解析已是过去式**：抖音会动态改版，凡是依赖 `_ROUTER_DATA` / `videoInfoRes` 的方案都随时可能失效。权威做法是跟真实浏览器行为走——`detail API + a_bogus`。
2. **签名算法的本质**：a_bogus 是"参数串 → 固定字节布局 + 哈希 + RC4 + 自定义 base64"的混淆签名，**不校验随机性**（浏览器信息串、时间戳都可以随机），但**必须结构正确**。这种设计让"签名可离线计算，但算法逆向有门槛"。
3. **Cookie 比 Header 更关键**：`ttwid` 是 detail API 的必要凭证，且由浏览器 JS 生成（带盐哈希，无法简单推导），只能靠"引导一次 + 定期续期"。
4. **反爬是"软性限流"而非"硬性封禁"**：偶发空 200 / 403，重试即可，但要注意频率。

### 8.2 对工程实践

1. **参考实现必须实测，不能轻信**：cache/、cache2/、parse-video 都标称"可工作"，但当前全部失效。验证手段很简单——装好依赖跑一遍真实链接。
2. **无头浏览器 + CDP 是绝佳的诊断工具**：抓真实网络请求（URL、headers、cookies、响应体）比逆向混淆 JS 高效得多，能直接暴露"页面到底调了什么接口"。
3. **用"最小参数集剥离"法定位硬性要求**：逐项删除参数/header 看哪些必须，快速缩小实现范围（最终发现只需要 a_bogus + ttwid）。
4. **临时性失败绝不能污染持久化状态**：空壳写缓存导致后续任务永久失败，这是本次最危险的隐性 bug。
5. **先验证再移植**：先在 Node/Python 用现成库验证算法正确，再花精力移植到 Go，避免"移植了错误算法"白做工。
6. **集成测试默认跳过、显式触发**：联网/依赖浏览器的测试用 `RUN_LIVE=1` 门控，避免破坏 CI 和常规 `go test`。

### 8.3 对未来改版的应对

- a_bogus 算法、参数集、ttwid 机制都可能随抖音更新而变。维护时优先**抓包对比真实浏览器请求**，确认差异点再小步调整。
- 若 detail API 走向更严的风控，可考虑：
  - 增加 ttwid 定期续期任务（当前在解析时惰性续期）；
  - 必要时退化到无头浏览器全程解析（方案 B）作为兜底。

## 九、部署与配置

新增环境变量（见 `.env.example`）：

```bash
# ttwid 持久化位置
DOUYIN_TTWID_FILE=./data/douyin_ttwid.json
# 无头浏览器路径（首次引导 ttwid 用）；留空自动探测 Edge/Chrome
DOUYIN_BROWSER_PATH=
```

- **Windows 本机**：自动探测 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` 等。
- **Linux 服务器**：需安装 Chromium 并显式配置 `DOUYIN_BROWSER_PATH=/usr/bin/chromium`；若无浏览器，解析会失败（返回 detail API 的具体错误）。
- **ttwid 有效期约 1 年**，续期由 `ttwid/check` 纯 HTTP 完成，无需浏览器常驻。
