# 启动与测试说明

本文说明网页版在本地开发、测试和打包时该执行哪些命令，以及 `go run`、`go build`、`start-web.ps1` 的使用时机。

## 启动脚本

- 源码模式：`scripts/windows/start-web.ps1`
- 打包模式：运行包里的 `start-web.ps1`

两者名字相同，但启动方式不同。

## 前置环境

源码模式需要：

- Go 1.26.5
- FFmpeg 与 FFprobe
- PowerShell
- `.env` 本地配置
- 硅基流动 API Key，可在 `.env` 中配置，也可管理员登录后在网页保存

仅测试界面和登录流程时，FFmpeg 不是必须；测试下载、转写时必须有 FFmpeg/FFprobe。

## 首次本地启动

在仓库根目录执行：

```powershell
.\scripts\windows\initialize-local.ps1
.\scripts\windows\start-web.ps1
```

说明：

- `initialize-local.ps1` 用来创建管理员账号，并确保本地数据库和 JWT 密钥可用。
- `start-web.ps1` 会读取 `.env`，缺失时从 `.env.example` 创建。
- 启动后访问 `http://127.0.0.1:8080`。
- 日志写入 `services/api_go/data/server.out.log` 和 `services/api_go/data/server.err.log`。

## 日常开发启动

推荐用：

```powershell
.\scripts\windows\start-web.ps1
```

这个脚本内部会执行：

```powershell
go run ./cmd/server
```

所以日常开发通常不需要手动再执行 `go run`。

适合场景：

- 修改 Go 服务代码后快速验证
- 修改内嵌网页版 HTML/CSS/JS 后快速验证
- 本地联调登录、解析、下载、转写流程

关闭启动脚本窗口会停止服务。

## 什么时候手动执行 go run

只有排查启动错误时，才建议手动执行：

```powershell
Set-Location services/api_go
go run ./cmd/server
```

原因：

- `start-web.ps1` 默认隐藏服务窗口，并把日志写到文件。
- 手动 `go run` 可以直接在终端看到错误堆栈。

管理命令也使用 `go run`，例如创建账号：

```powershell
Set-Location services/api_go
go run ./cmd/admin create-user --username owner --display-name Owner --role admin --password-file <private-file>
```

注意：服务端和管理命令必须使用同一个 `DATABASE_PATH`。

## 什么时候执行 go build

日常开发和普通测试不需要执行 `go build`。

只有准备生成可分发运行包时，才需要构建：

```powershell
.\scripts\windows\build-local-package.ps1 -FFmpegBin C:\ffmpeg\bin
```

这个脚本会执行：

```powershell
go build ... ./cmd/server
go build ... ./cmd/admin
```

并输出：

```text
dist\douyin-capture-windows-<版本号>
```

生成后的运行包包含：

- `douyin-capture-server.exe`
- `douyin-capture-admin.exe`
- `start-web.ps1`
- `initialize-admin.ps1`
- `.env.example`
- 可选的 `tools\ffmpeg.exe` 和 `tools\ffprobe.exe`

## 运行已构建包

进入 `dist\douyin-capture-windows-<版本号>` 后执行：

```powershell
.\initialize-admin.ps1
.\start-web.ps1
```

打包模式的 `start-web.ps1` 不再执行 `go run`，而是启动：

```text
douyin-capture-server.exe
```

所以使用运行包的机器不需要安装 Go。

打包模式也会读取运行包目录下的 `.env`。需要改端口时，修改：

```env
HTTP_ADDR=0.0.0.0:7788
```

如果打包时传入了 `-FFmpegBin C:\ffmpeg\bin`，运行包也不需要目标机器单独安装 FFmpeg。

## 测试建议

### 只测界面

执行：

```powershell
.\scripts\windows\start-web.ps1
```

然后在浏览器检查：

- 登录页
- 新建任务页
- 任务列表
- 任务详情
- 设置页
- 移动端宽度：`375px`、`430px`、`768px`

### 测完整流程

需要确认：

- `.env` 中 `FFMPEG_PATH` 和 `FFPROBE_PATH` 可用
- 已配置硅基流动 API Key
- 服务端可以访问抖音视频资源

测试路径：

1. 登录。
2. 粘贴抖音分享文本。
3. 先选择“解析作品信息”。
4. 再测试“下载无水印视频”。
5. 最后测试“提取视频文案”或“提取文案并下载视频”。

### 跑自动化测试

后端测试：

```powershell
Set-Location services/api_go
go test ./...
```

如果遇到 `go-build` 缓存目录权限问题，通常不是业务代码错误。可以换一个可写缓存目录后再跑：

```powershell
$env:GOCACHE = "$PWD\.gocache"
go test ./...
```

一次性检查：

```powershell
.\scripts\check.ps1
```

## 常见判断

| 目的 | 应该执行 |
| --- | --- |
| 本地启动网页版 | `.\scripts\windows\start-web.ps1` |
| 首次创建管理员 | `.\scripts\windows\initialize-local.ps1` |
| 看 Go 启动错误 | `go run ./cmd/server` |
| 创建或管理用户 | `go run ./cmd/admin ...` |
| 生成分发包 | `.\scripts\windows\build-local-package.ps1 -FFmpegBin C:\ffmpeg\bin` |
| 运行分发包 | 运行包里的 `.\start-web.ps1` |
| 普通开发测试 | 不需要 `go build` |
