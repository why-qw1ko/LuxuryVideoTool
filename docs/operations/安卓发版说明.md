# 安卓版本发布

管理员在网页后台的“安卓发版”中管理更新包。安卓每次启动自动检查一次，登录后进入主页显示更新弹窗；“我的”页面或更新弹窗中的“重新检查”可以手动检查。回到前台和启动检查完成后的服务器切换不会自动发起检查。

## 首次启用

先部署带发版接口的新 Go 服务，再手动安装一次带更新功能的安卓客户端。已经安装的旧客户端没有检查更新代码，不能凭服务端配置自动获得此功能。

客户端从当前配置的服务器读取更新，不需要先登录。尚未填写服务器地址时，先配置连接。

## 制作 APK

1. 在 Android Studio 打开仓库的 `android` 目录。
2. 修改 `app/build.gradle.kts` 中的 `versionCode` 和 `versionName`。每个新安装版本递增 `versionCode`，例如从 `1` 改为 `2`；`versionName` 是展示给用户的版本名称。
3. 本机已配置 release 自动签名。将 Android Studio 的 Gradle JDK 设置为 **JDK 21**，然后运行 `:app:assembleRelease`；不需要每次重新创建或选择签名。
4. 保持应用包名 `com.buleng.luxuryvideo`。上传完整 APK，不能上传 AAB、分包集合或 ZIP 压缩包；单个文件最大 256 MiB。

也可以在仓库的 `android` 目录使用 JDK 21 执行：

```powershell
.\gradlew.bat :app:assembleRelease
```

签名 APK 输出到 `android/app/build/outputs/apk/release/app-release.apk`（相对仓库根目录）。构建通过本机的 `android/key.properties` 读取签名配置，密钥位于 `secrets/android/luxuryvideo-release.jks`，别名为 `luxuryvideo-release`。每个后续版本都复用这把签名；缺少本地配置或密钥时，release 构建会明确报错。

服务端会从 APK 读取包名、版本编号和版本名称，页面中这些字段只读。每次发布不需要修改 Go 服务版本，也不需要重新部署服务。

覆盖安装要求签名兼容。如果当前手机使用 Android Studio 的调试包，而正式 APK 使用另一份签名，第一次迁移需要先卸载旧包，再安装正式包。卸载会清除该应用的本机数据，服务器中的账号和任务不受影响。

## 上传和发布

1. 用管理员账号登录网页，进入“管理 → 安卓发版”。
2. 选择 APK 并上传，等待上传和解析完成。上传只替换草稿，不影响手机正在获取的已发布版本。
3. 核对版本信息，填写更新说明，设置这个版本发布后是否要求强制更新。
4. 保存草稿后发布。发布后，配置同一服务器且版本编号更低的客户端会在下次检查时发现更新。

发布新包时版本编号必须高于已发布版本。相同 APK、相同版本编号可以重新编辑更新说明后发布；不能用相同编号替换不同 APK 或回退到更低编号。

## 远程控制强制更新

“当前已发布版本”的强制更新开关和草稿中的开关分开保存。调整线上开关后，点击“保存当前更新策略”才会生效，不需要重新上传 APK。草稿中的强制更新设置会在发布时覆盖线上策略；如果关闭线上强制更新后，再发布仍开启强制更新的草稿，线上强制更新会重新开启。

- 关闭：较旧客户端提示新版，用户可以选择“取消更新”继续使用。
- 开启：所有低于当前发布版本的客户端必须更新，弹窗隐藏取消按钮，返回键和点击外部均不能关闭；下载失败或系统安装取消后仍停留在更新提示，可以重试。
- 已安装当前版本或更高版本的客户端不会被强制更新。

管理员修改强制更新开关后，在客户端下次启动自动检查或用户手动检查时生效。弹窗提供“重新检查”按钮，不进行定时检查；管理员关闭强制后，用户点击该按钮或重新启动应用并检查成功，弹窗会显示“取消更新”，可以关闭并继续使用。

首次检查遇到断网、旧服务没有此接口等情况，不会被误判为强制更新。已经确认过的强制策略按服务器缓存，检查失败时保留重试，避免断网直接绕过。切换服务器不会继承另一个服务器的强制策略。

## 下载和安装

客户端显示下载进度，下载后核对文件大小、SHA-256、包名、实际版本编号和签名兼容性，再打开系统安装界面。首次可能需要按系统提示允许本应用安装未知应用；授权后可以继续安装，最终仍由用户在系统界面确认。

更新包下载到应用专用缓存，不混入作品下载记录。系统清理缓存或安装取消后可以重新下载。发布记录和 APK 独立于任务文件，任务删除和媒体过期清理不会删除更新包。

## 部署与备份

保留 Go 服务当前的数据目录及数据库，按照原部署方式持久化、备份。迁移服务器时同时迁移发布记录和 APK 文件；只复制数据库或者只复制安装包都不足以恢复完整发布状态。

若前方还有反向代理，需要允许至少 256 MiB 的上传请求，并为 APK 上传设置足够的超时时间。上传异常时先看页面错误信息及代理限制，再重试；未完成的上传不会自动发布。

请将仓库根目录下的 `secrets/android/luxuryvideo-release.jks` 和 `android/key.properties` 一起私下备份；迁移构建电脑时需要恢复这两项，并继续使用原签名。它们均由 Git 忽略，不得提交或放入公开源码备份。

发布签名和本地签名配置保留在构建环境，不上传到发版后台。后台只上传生成的 APK。
